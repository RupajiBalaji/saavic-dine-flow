1. SUPABASE PROJECT SETUP (STEP-BY-STEP)
================================================================================

Step 1: Create a Supabase Project
  1. Go to https://supabase.com and log in (or sign up).
  2. Click "New Project".
  3. Enter:
     - Name: Saavic Dine Flow (or your preferred name)
     - Database Password: Create a strong password (save this safely)
     - Region: Choose the closest region (e.g., South Asia - Mumbai)
  4. Click "Create new project" and wait 1–2 minutes for the database to provision.

Step 2: Collect Your API Keys & Project URL
  1. In your Supabase dashboard, navigate to Project Settings -> API (or Settings -> Configuration -> API).
  2. Copy the following values:
     - Project URL: e.g. https://[YOUR_PROJECT_REF].supabase.co
     - Project Ref ID: e.g. [YOUR_PROJECT_REF]
     - Project API Keys:
       * "anon" / "public" (or new publishable key starting with sb_publishable_)
       * "service_role" (secret key starting with sb_secret_ or legacy service_role JWT).
         IMPORTANT: Keep the service_role key secure! It bypasses RLS and is 
         required by the backend server for order processing and admin functions.

Step 3: Run the SQL Migrations
  1. In your Supabase dashboard, go to the "SQL Editor" in the left sidebar.
  2. Click "New query".
  3. Copy and run the scripts in Sections 4, 5, and 6 in order (or run them together).

Step 4: Configure Authentication
  1. In your Supabase dashboard, go to "Authentication" -> "Providers" -> "Email".
  2. Ensure "Enable Email provider" is switched ON.
  3. (Recommended for quick testing): Under "Authentication" -> "URL Configuration" / "Email Templates",
     you can turn off "Confirm email" if you want staff signups to activate immediately.

Step 5: Set up your local .env
  1. Update the .env file in the root directory of this project with your Supabase values.
     (See Section 2 for the exact template).

3. AUTHENTICATION & STAFF ROLES EXPLAINED
================================================================================

Roles defined in the database:
- SUPER_ADMIN  : Full cafe access, assign staff roles, manage all settings
- MANAGER      : Full operational management (menu, tables, discounts, inventory, record cash payments, view bills, close tables)
- KITCHEN_STAFF: View live kitchen orders, update prep status (Accepted, Preparing, Ready)

Customer Portal:
- Customers DO NOT need to sign up or log in. They simply scan the QR code 
  (e.g., /t/table-01) and order immediately.

Staff Login:
- Staff users log in via `/auth`.
- Newly registered staff will not see the dashboard until an existing SUPER_ADMIN 
  assigns them a role (or until you run the SQL in Section 7).

CREATE TABLE public.profiles (
  id uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  full_name text,
  email text,
  phone text,
  active boolean NOT NULL DEFAULT true,
  created_at timestamptz NOT NULL DEFAULT now()
);
GRANT SELECT, INSERT, UPDATE ON public.profiles TO authenticated;
GRANT ALL ON public.profiles TO service_role;
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;

CREATE TABLE public.user_roles (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  role public.app_role NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (user_id, role)
);
GRANT SELECT ON public.user_roles TO authenticated;
GRANT ALL ON public.user_roles TO service_role;
ALTER TABLE public.user_roles ENABLE ROW LEVEL SECURITY;

CREATE OR REPLACE FUNCTION public.has_role(_user_id uuid, _role public.app_role)
RETURNS boolean LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public AS $$
  SELECT EXISTS (SELECT 1 FROM public.user_roles WHERE user_id = _user_id AND role = _role);
$$;

CREATE OR REPLACE FUNCTION public.is_staff(_user_id uuid)
RETURNS boolean LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public AS $$
  SELECT EXISTS (SELECT 1 FROM public.user_roles WHERE user_id = _user_id);
$$;

CREATE POLICY "own profile read" ON public.profiles FOR SELECT TO authenticated USING (id = auth.uid() OR public.is_staff(auth.uid()));
CREATE POLICY "own profile update" ON public.profiles FOR UPDATE TO authenticated USING (id = auth.uid());
CREATE POLICY "own profile insert" ON public.profiles FOR INSERT TO authenticated WITH CHECK (id = auth.uid());
CREATE POLICY "roles readable by staff" ON public.user_roles FOR SELECT TO authenticated USING (user_id = auth.uid() OR public.has_role(auth.uid(),'SUPER_ADMIN'));

CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER SET search_path = public AS $$
BEGIN
  INSERT INTO public.profiles (id, full_name, email)
  VALUES (NEW.id, COALESCE(NEW.raw_user_meta_data->>'full_name',''), NEW.email)
  ON CONFLICT (id) DO NOTHING;
  RETURN NEW;
END; $$;

CREATE TRIGGER on_auth_user_created AFTER INSERT ON auth.users
FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();

-- Run this optional block in Supabase SQL Editor if you want to enable these features:

-- 1. Table Service / Waiter Calls
CREATE TYPE public.service_request_type AS ENUM ('CALL_WAITER','REQUEST_WATER','REQUEST_BILL','CLEAN_TABLE');
CREATE TYPE public.service_request_status AS ENUM ('PENDING','ATTENDED','CANCELLED');

CREATE TABLE public.table_service_requests (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  table_id uuid NOT NULL REFERENCES public.cafe_tables(id) ON DELETE CASCADE,
  session_id uuid REFERENCES public.table_sessions(id) ON DELETE CASCADE,
  type public.service_request_type NOT NULL DEFAULT 'CALL_WAITER',
  status public.service_request_status NOT NULL DEFAULT 'PENDING',
  notes text,
  created_at timestamptz NOT NULL DEFAULT now(),
  attended_at timestamptz,
  attended_by uuid REFERENCES auth.users(id)
);

ALTER TABLE public.table_service_requests ENABLE ROW LEVEL SECURITY;
GRANT SELECT, INSERT ON public.table_service_requests TO anon, authenticated;
GRANT ALL ON public.table_service_requests TO service_role;
CREATE POLICY "requests public insert" ON public.table_service_requests FOR INSERT TO anon, authenticated WITH CHECK (true);
CREATE POLICY "requests staff read" ON public.table_service_requests FOR SELECT TO authenticated USING (public.is_staff(auth.uid()));
CREATE POLICY "requests staff update" ON public.table_service_requests FOR UPDATE TO authenticated USING (public.is_staff(auth.uid()));

ALTER TABLE public.table_service_requests REPLICA IDENTITY FULL;
ALTER PUBLICATION supabase_realtime ADD TABLE public.table_service_requests;

-- 2. Customer Reviews & Ratings
CREATE TABLE public.customer_reviews (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  session_id uuid REFERENCES public.table_sessions(id) ON DELETE SET NULL,
  table_id uuid REFERENCES public.cafe_tables(id) ON DELETE SET NULL,
  rating int NOT NULL CHECK (rating >= 1 AND rating <= 5),
  food_rating int CHECK (food_rating >= 1 AND food_rating <= 5),
  service_rating int CHECK (service_rating >= 1 AND service_rating <= 5),
  feedback text,
  customer_name text,
  customer_phone text,
  created_at timestamptz NOT NULL DEFAULT now()
);

ALTER TABLE public.customer_reviews ENABLE ROW LEVEL SECURITY;
GRANT INSERT ON public.customer_reviews TO anon, authenticated;
GRANT SELECT ON public.customer_reviews TO authenticated;
GRANT ALL ON public.customer_reviews TO service_role;
CREATE POLICY "reviews public insert" ON public.customer_reviews FOR INSERT TO anon, authenticated WITH CHECK (true);
CREATE POLICY "reviews staff read" ON public.customer_reviews FOR SELECT TO authenticated USING (public.is_staff(auth.uid()));

-- 3. Product Recipes (Inventory Auto-Deduction)
CREATE TABLE public.product_recipes (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  product_id uuid NOT NULL REFERENCES public.products(id) ON DELETE CASCADE,
  inventory_item_id uuid NOT NULL REFERENCES public.inventory_items(id) ON DELETE CASCADE,
  quantity_used numeric(12,3) NOT NULL CHECK (quantity_used > 0),
  UNIQUE (product_id, inventory_item_id)
);

ALTER TABLE public.product_recipes ENABLE ROW LEVEL SECURITY;
GRANT SELECT ON public.product_recipes TO authenticated;
GRANT ALL ON public.product_recipes TO service_role;
CREATE POLICY "recipes staff read" ON public.product_recipes FOR SELECT TO authenticated USING (public.is_staff(auth.uid()));
CREATE POLICY "recipes manager write" ON public.product_recipes FOR ALL TO authenticated 
  USING (public.has_role(auth.uid(),'MANAGER') OR public.has_role(auth.uid(),'SUPER_ADMIN'))
  WITH CHECK (public.has_role(auth.uid(),'MANAGER') OR public.has_role(auth.uid(),'SUPER_ADMIN'));

-- Trigger: Automatically deduct inventory when order items are placed
CREATE OR REPLACE FUNCTION public.deduct_inventory_for_order()
RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER SET search_path = public AS $$
BEGIN
  UPDATE public.inventory_items inv
  SET stock = GREATEST(0, inv.stock - (r.quantity_used * NEW.quantity))
  FROM public.product_recipes r
  WHERE r.product_id = NEW.product_id
    AND r.inventory_item_id = inv.id;
  RETURN NEW;
END;
$$;

CREATE TRIGGER on_order_item_deduct_stock
AFTER INSERT ON public.order_items
FOR EACH ROW EXECUTE FUNCTION public.deduct_inventory_for_order();

11. RAZORPAY GATEWAY SETUP GUIDE (HOW TO LINK LATER)
================================================================================

Good news: The application is ALREADY architected with a "Counter / Cash Fallback 
Mode". This means you CAN connect your Supabase database and run/test the entire 
app end-to-end right now without Razorpay!

--------------------------------------------------------------------------------
A. HOW THE APP OPERATES RIGHT NOW (WITHOUT RAZORPAY KEYS)
--------------------------------------------------------------------------------
1. In `src/lib/cafe.server.ts`, the server automatically detects if Razorpay keys 
   are missing (`razorpayConfigured() = false`).
2. When a customer taps "Pay Bill" in the Orders tab, the app smoothly responds:
   "Online payment is not configured yet. Please pay at the counter — our staff 
   can record your payment."
3. The manager/staff can then open `/admin`, find the table, and click "Record Cash 
   Payment" (`markCashPaid`).
4. This marks the session as `CASH_PAID`, marks the table as `PAID`, records a 
   payment row in the `payments` table, and logs the audit event.
5. You can test ordering, table states, kitchen statuses, and sessions completely 
   free without needing any payment gateway!

--------------------------------------------------------------------------------
B. HOW TO CONNECT RAZORPAY LATER (WHEN YOU ARE READY)
--------------------------------------------------------------------------------
When you are ready to accept UPI, Google Pay, PhonePe, and Debit/Credit Cards 
directly from customer phones, follow these 4 simple steps:

STEP 1: Create a Razorpay Account
  1. Sign up at https://razorpay.com.
  2. In the top-left of the Razorpay dashboard, toggle the mode to "Test Mode" 
     (for testing with dummy money) or "Live Mode" (for actual cafe business).

STEP 2: Generate API Key & Secret
  1. In Razorpay Dashboard, go to: Account & Settings -> API Keys (under Developer controls).
  2. Click "Generate Key" (or "Regenerate Test Key").
  3. Copy:
     - Key ID: looks like `rzp_test_xxxxxxxxxxxxxx` (or `rzp_live_...`)
     - Key Secret: looks like `xxxxxxxxxxxxxxxxxxxxxxxx`

STEP 3: Add the Keys to Your `.env` File
  Open your project's `.env` file and replace the Razorpay variables:

  RAZORPAY_KEY_ID="rzp_test_xxxxxxxxxxxxxx"
  RAZORPAY_KEY_SECRET="your_actual_key_secret_here"
  RAZORPAY_WEBHOOK_SECRET="create_any_random_secret_passphrase_here"

  *Restart your local dev server (`npm run dev`) after editing `.env`.*

STEP 4: Set Up the Webhook in Razorpay (For Instant Payment Confirmations)
  Razorpay webhooks guarantee that even if a diner's browser battery dies or drops 
  Wi-Fi right after paying UPI, your database is still updated instantly.

  1. In Razorpay Dashboard, go to: Account & Settings -> Webhooks.
  2. Click "Add New Webhook".
  3. Enter:
     - Webhook URL: `https://your-deployed-domain.com/api/public/razorpay-webhook`
       (For local testing on localhost, you can use ngrok: e.g. `https://xxxx.ngrok-free.app/api/public/razorpay-webhook`)
     - Secret: Enter the exact same secret you set for `RAZORPAY_WEBHOOK_SECRET` in `.env`.
     - Alert Email: Your cafe alert email.
     - Active Events: Check these 3 events:
       * `order.paid`
       * `payment.captured`
       * `payment.failed`
  4. Click "Create Webhook".

--------------------------------------------------------------------------------
C. HOW THE PAYMENT FLOW AUTOMATICALLY SWITCHES
--------------------------------------------------------------------------------
Once you add the Razorpay keys to `.env`:
1. The backend automatically switches `razorpayConfigured()` to `true`.
2. When the customer clicks "Pay Bill", the app calls `createBillPayment`, which 
   creates an authentic order with Razorpay in paise (e.g. ₹299 -> 29900 paise).
3. The official Razorpay Checkout popup automatically opens on the customer's phone.
4. The customer pays with GPay, PhonePe, Paytm, QR, or Card.
5. On success, the frontend sends the payment signature to `verifyBillPayment`.
6. The server cryptographically validates the HMAC-SHA256 signature against your 
   `RAZORPAY_KEY_SECRET`.
7. Once verified:
   - Database table `table_sessions` payment_state updates to `PAID`.
   - Table status in `cafe_tables` updates to `PAID`.
   - Realtime event notifies the Manager Dashboard instantly.

13. CONTACTLESS DINE-IN JOURNEY: "ZERO-GETUP" POLICY & BILL DELIVERY
================================================================================

This policy ensures diners enjoy a seamless, contactless experience without ever
having to leave their table, while protecting the cafe against prank/fake orders:

--------------------------------------------------------------------------------
STEP 1: TABLE QR CODE SCAN & AUTO TABLE IDENTIFICATION
--------------------------------------------------------------------------------
1. Each of the 20 tables has its own distinct QR code (generated in `/admin/qr`).
2. Scanning the QR opens the table's digital menu: `/t/table-01`, `/t/table-02`, etc.
3. The table identity is locked to the QR code, so the kitchen always knows 
   the exact table number where food should be delivered.

--------------------------------------------------------------------------------
STEP 2: MANDATORY PHONE NUMBER VERIFICATION (PRE-ORDER FRAUD SHIELD)
--------------------------------------------------------------------------------
1. Before placing an order, the diner MUST enter and verify their 10-digit mobile number.
2. Why this is essential:
   - Prevents fake/prank orders from walk-ins or trolls.
   - Binds the active table session to a real human diner.
   - Provides the official mobile number for order status updates and tax invoices.
3. Once verified, the diner is granted an active table token stored in their device's
   browser session. If they place multiple orders (e.g. second rounds of drinks/desserts),
   they do NOT need to re-verify during the same sitting.

--------------------------------------------------------------------------------
STEP 3: KITCHEN PREPARATION & DINING PHASE
--------------------------------------------------------------------------------
1. Kitchen Staff receives the order on their live KDS screen (`/admin/kitchen`).
2. Food is prepared and served directly to the diner's table.
3. The diner continues enjoying their meal with zero need to stand up.

--------------------------------------------------------------------------------
STEP 4: BILL INSPECTION & PAYMENT (FROM THE TABLE)
--------------------------------------------------------------------------------
1. When the diner finishes eating, they have two simple ways to view their bill:
   - Option A: Tap the "Orders / Bill" tab on their phone screen.
   - Option B: If they closed the browser tab, simply re-scan the table's QR code.
     The system automatically resumes their active session and shows their live bill!
2. Payment Options:
   - Online Payment at Table (UPI / GPay / PhonePe / Card / Razorpay):
     * Diner taps "Pay Bill", enters UPI PIN / Card on their phone, and pays.
     * The customer NEVER gets up from the table.
   - Cash Payment at Counter:
     * Diner can walk to the cashier counter (or call the waiter) and pay cash.
     * The cashier marks "Record Cash Payment" on `/admin/tables`.

--------------------------------------------------------------------------------
STEP 5: BILL & RECEIPT DELIVERY
--------------------------------------------------------------------------------
1. For Online Payers (Self-Checkout from Table):
   - As soon as payment succeeds, a prominent "Download Bill (PDF / E-Receipt)" 
     button appears on the customer's phone screen.
   - Clicking it immediately downloads their official branded tax invoice with:
     * Cafe Branding & Address
     * Table Name & Bill Number
